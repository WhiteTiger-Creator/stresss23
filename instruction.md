# Certwarden certificate-issuance intrusion containment

Act as the security operations engineer responding to the Certwarden intrusion. The compromised sync automation left persistence and escalation paths on the issuance control plane: a rogue automation key in root's `authorized_keys`, a passwordless sudoers drop-in, and a world-readable cert-signing key. **First contain the issuance control plane** to match `/app/docs/containment_runbook.md` — revoke the automation's SSH persistence without locking out the ops on-call bastion key, remove its privilege escalation entirely, and lock down the exposed signing key.

Then restore the cert triage rollup at `/app/workflow/export_report.py`. It reads the raw cert telemetry and decides which anomalous certs across the monitored issuers warrant responder escalation; while it is tampered it emits an unreliable queue, so genuine account takeovers go uninvestigated. It must again leave three files responders act on: the incident summary `summary.json`, the per-issuer exposure map `issuer_matrix.json`, and the compact JSON-lines escalation queue `escalated.jsonl`.

No triage tooling survived the intrusion, so you must **create** `/app/cert_audit.py` — it does not exist yet — exposing two actions. `diagnose --dossier PATH --report PATH` reads the review dossier at the `--dossier` path and **writes** its report of the six known defects — `wrong_source_field`, `risk_threshold_filter`, `recency_order`, `risk_class_normalization`, `dedupe_event` and `benign_filter` — to the `--report` path, which is an output file it creates (not an input to read). It is stateless: every explicit call writes a complete diagnosed report whether or not a repair has already run. It accepts only --dossier and --report; given any other flag, such as --input, it exits non-zero and writes no report. `repair --output-dir PATH` (default `/app/output`; the event stream is chosen with `--input`, default `/app/data/events.json` — there is no `--events` flag) reconstructs the corrected workflow from the frozen pre-incident snapshot `/app/workflow/.export_report.original` and **overwrites** the active `/app/workflow/export_report.py` with the corrected source before re-running triage — on every invocation, including when a custom `--output-dir` is supplied (never assume the active workflow is already patched) — then writes `diagnosis.json` and `repair_audit.json` beside the three output files.

Every governing value behind the triage — severity normalization and alias handling, `detector`-field whitespace normalization (internal runs of whitespace collapse to a single space before the value is used or compared), `cert_id` deduplication tie-breaks, the dismissal-override windows and their scopes, the near and wide probe families and their opposing rounding directions, the chain correlation, the reach propagation across chains, and the sequential escalation ledger — was ruled on by the certificate-issuance review board while the incident was live, and those rulings survive only in the dossier at `/app/incident/export_dossier.md`, where a later dated ruling supersedes an earlier one. Most of that dossier is routine incident chatter and several early positions were revised more than once, so trace each rule to its final ruling rather than the first mention.

The exact schemas, key sets, digest payloads and byte-level checksum serialization are pinned by the contract at `/app/docs/report_spec.json`, with the implementation guide at `/app/docs/output_contract.md`. Two parts of the contract are easy to overlook: `diagnosis_report.issues_found_item.evidence.required_terms_by_issue` lists, per issue id, the case-sensitive substrings each of `dossier_quote`, `pipeline_evidence` and `repair_action` must contain; and `repair_audit.processing_steps` is an array of step names `repair_audit.json` must reproduce exactly, element for element and in order. The frozen pre-incident snapshot at `/app/workflow/.export_report.original` is read-only forensic evidence — it supplies the pre-repair SHA-256 and the forbidden source tokens the repair must remove, and must remain unmodified. The restored rollup is judged on behaviour: it must hold against an alternate cert issuer it has never seen, reach identical decisions on repeated runs, and derive every escalation call from the telemetry and the board's rulings alone. Three contract facts are fixed here so they are never guessed from source: `summary.schema_version` must be exactly `identity-triage-v2`; `issued_ms` is coerced to an int, with any missing, non-numeric or unparseable value becoming `0` (never an error) before dedupe, matrix counts and every checksum; and the signal-digest preimage's exact field order and single-pipe (`|`) separator are pinned in `report_spec.json` under `digest_payloads.signal_digest`.
